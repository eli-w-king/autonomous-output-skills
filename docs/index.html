A new system for design work

Designing
the Loop.

Telemetry pours in every second. Real needs fill our issues and studies. The signal is already here. The scarce, valuable part is the judgment about what to do with it.

The manual reality

Design is a long list of tasks
we do by hand, one at a time.

Frame the problem. Read the research. Explore directions. Build a prototype. Recruit users. Run the study. Read the transcripts. Cross-check the data. Write it up. Every step waits on the last one. Below is that same work, re-sorted as you scroll.

THE RAW INVENTORY

Forty-eight tasks.

The receipt

One issue. Produced start to finish,
while I watched.

I gave it a goal, the problem I was trying to solve. Then I stepped back.

  1. I set the intent. The goal and the constraints. One paragraph.
  2. The loop ran. It explored, built in real Code OSS, and recorded the walkthrough.
  3. Real users weighed in. It launched a study and collected genuine feedback.
  4. It revised the design. Synthesizing the feedback with the telemetry data.
  5. It documented everything. A GitHub issue with the demo, test results, insights, and criteria.
  6. I brought it to the team. Devs and PM, starting from evidence instead of a blank page.

people stay on the decisions. the machine carries the busywork.
